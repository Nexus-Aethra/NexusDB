# NexusDB 存储层重构目录（2026-11）

> **状态：规划中，Phase 1 已定义待实施**
> **目标：** 消除 LCB-Tree 固定 16KB 页粒度带来的写放大，同时**不**推翻
> COW 语义、`vpid→pid` 映射层与页粒度 GC。
> **总纲：** 保留 B+Tree，把"每笔写触发一次页 COW"变成"每批写触发一次页 COW"，
> 并让叶页从"内联 value"变为"存指针"以提升密度、缩小树规模。

---

## 1. 为什么做这次重构

对照实验对象：**Lavik**（`git@github.com:eloqdata/lavik.git`，v0.3.0，C++23，
本地 clone 目录自定），同口径公开数据为 10M keys / 1KiB value / 16 vCPU 下
**945K SET/s、1.16M GET/s**；NexusDB 当前 memtier 写重 1:1 约 **153K ops/s**
（`docs/AGENTS.md`）、覆盖写约 **167K SET/s**（`docs/plans/2026-08-05-resp-write-path-performance.md`）。

根因不是语言或成熟度，而是**写入单位与存储结构不匹配**：
NexusDB 改 32 字节要重写整个 16KB 页，Lavik 只 append 一条 ~70B 记录并改内存索引指针。
硬件侧也不支持 16KB 这个选择——NVMe 主机逻辑块为 512B/4KB，FTL 自行合并并屏蔽
NAND page/erase-block 细节，**16KB 是 LCB-Tree 自身的选择**。

## 3. 实施顺序与依赖

```
Phase 0  perf 归因（前置，未开始）
   └─ 证明页 COW 是主要成本，避免重蹈 2026-08-05 微批覆辙

1-B-1  指针机制落地（仅大 value，保留 inline 小 value）
   └─ 依赖：无（独立可验证）

1-B-2  密度收益验证（叶页数 / 树深 / 缓存命中率）
   └─ 依赖：1-B-1

1-B-3  memtable + 批量折叠          ← 写放大收益的完整兑现点
   └─ 依赖：1-B-1, 1-B-2（数据支撑）

1-B-4  全量指针化（可选）
   └─ 依赖：1-B-3 数据

Phase 2  GC 与折叠协同（可选）
Phase 3  映射层瘦身 / LSM 化（远期，需单独评审）
```

**关键依赖说明**：1-B-1 与 memtable（框架 §3）**互相独立**，可并行开发；
但**写放大的完整收益只在两者叠加后出现**（1-B-3）。任一部分单独上线都不承诺性能数字。

## 4. 已确定的架构决策

| 决策 | 结论 | 理由 |
|---|---|---|
| B+Tree 去留 | **保留** | SQL 需要有序范围扫；LSM 读放大与范围扫冲突 |
| COW 语义 | **保留** | 免费提供快照；删它需补 MVCC |
| `vpid→pid` 映射层 | **Phase 1 保留** | 是 GC 便宜的承重结构；删除需 GC 全量重构 |
| GC | **Phase 1 不改** | 页粒度 liveness 继续工作 |
| memtable | **引入**（有界内存） | 独立解决普通写放大 |
| MVCC | **不引入** | 当前事务已由 RC + RYOW + OCC 覆盖（`AGENTS.md` F61/F62） |
| inline 小 value | **第一阶段保留** | 读路径不回归，改动面最小 |
| 复合结构指针化 | **第一阶段不做** | 只做 String + 溢出路径 |

## 5. 待决问题汇总

以下问题横跨两份文档，实施前需逐条确认：

**来自框架文档（§8）：**
1. memtable 数据结构：`BTreeMap` 起步 vs 直接跳表？
2. memtable 容量默认值（需 Phase 0 基线后定）
3. 折叠触发：仅容量阈值，还是加时间阈值控尾延迟？
4. memtable 是否按 `(db, table)` 分片以支持并行折叠？
5. 旧 memtable 折叠后立即丢弃，还是保留为不可变快照源？

**来自指针化文档（§8）：**
6. 是否保留 inline 小 value？（建议保留）
7. 数据页页类型：复用 `PageType::Overflow(4)` 还是新增 `Data(6)`？
8. 指针是否加 flags 字节为 CRC/压缩预留？（建议不加，用 marker 高位扩展）
9. 复合结构是否同步指针化？（建议第一阶段不做）
10. 数据页是否也纳入 memtable 批量写？

## 6. 通用约束（所有改进项共享）

1. **性能门槛**：多轮交错 A/B（≥ 5 轮），数据目录每次全新，报告均值与方差；
   不接受单次采样。
2. **正确性门槛**：`cargo test --workspace` 全绿 + clippy 0 警告；
   大 value 读写 roundtrip、kill -9 恢复、RYOW 穿透必须建回归。
3. **禁止事项**：不为性能关闭 WAL、削弱崩溃一致性、放宽错误处理。
4. **回退**：每项改进由配置开关控制，默认 `off`，不达门槛即回退，代码保留不启用。
5. **协议零感知**：`crates/network` 与对外行为不变。
